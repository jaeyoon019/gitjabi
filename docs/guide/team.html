팀 작업

여럿이 같은 repo에서 작업할 때 달라지는 점만 알아봅니다. 개인 작업 한 바퀴에 “먼저 받아오기”와 “갈래 나누기”가 더해집니다.

이 페이지의 순서

  1. 1혼자일 때와 다른 점GitHub는 모두가 쓰는 공용 보관함
  2. 2시작하기초대 수락과 clone
  3. 3작업할 때의 습관시작 전에 pull, 올리기 전에 pull
  4. 4push가 거절될 때가장 먼저 만나는 상황
  5. 5branch로 따로 작업하기main을 건드리지 않고 작업
  6. 6Pull Request로 합치기GitHub 화면에서 하는 일
  7. 7충돌이 났을 때같은 줄을 같이 고쳤을 때
  8. 8팀 작업 습관이것만 지켜도 사고가 줄어듭니다

혼자일 때와 다른 점

혼자 작업할 때는 GitHub의 내용이 항상 내가 올린 그대로였습니다. 팀 작업에서는 내가 모르는 사이에 팀원이 GitHub에 새 기록을 올릴 수 있습니다. GitHub는 모두가 함께 쓰는 공용 보관함이고, 각자의 컴퓨터는 그 사본입니다.

내 컴퓨터내 사본
⇄push / pull
GitHub모두의 공용 보관함
⇄push / pull
팀원 컴퓨터팀원의 사본

push는 내 기록을 보관함에 올리는 것, pull은 보관함의 새 기록을 내 사본으로 받아오는 것입니다. 그래서 팀 작업의 핵심은 작업하기 전에 최신 상태를 받아 오는 것입니다.

시작하기

1. repo 초대 수락하기

repo 소유자가 팀원을 Collaborator로 초대하면(repo의 Settings → Collaborators), 초대받은 사람은 이메일이나 GitHub 알림에서 수락해야 합니다. 수락해야 이 repo에 직접 push할 수 있습니다.

2. 내 컴퓨터로 repo 복사하기 (clone)

repo 화면의 초록 Code 버튼을 눌러 HTTPS 주소를 복사한 뒤, repo를 둘 폴더로 이동해서 clone합니다. clone은 처음 한 번만 합니다.

$ cd 작업할폴더 repo를 둘 폴더로 이동합니다 $ git clone 복사한주소 $ cd repo이름 새로 생긴 repo 폴더 안으로 들어갑니다

clone하면 지금 있는 폴더 안에 repo 이름의 폴더가 새로 생깁니다. 이미 clone해 둔 repo라면 다시 할 필요 없이 그 폴더 안에서 git pull만 하면 됩니다.

작업할 때의 습관

개인 작업의 한 바퀴에 pull이 두 번 들어간다고 생각하면 됩니다.

  1. 1
    git pull작업을 시작하기 전에 팀원이 올린 최신 내용을 받아옵니다.
  2. 2
    파일 수정평소처럼 작업합니다.
  3. 3
    git add → git commit -m "메시지"내 컴퓨터에 기록합니다.
  4. 4
    git pull올리기 직전에 한 번 더 받아옵니다. 작업하는 사이에 팀원이 올렸을 수 있습니다.
  5. 5
    git pushGitHub에 올립니다.

push가 거절될 때

팀 작업을 시작하면 가장 먼저 만나는 상황입니다. 이런 메시지가 나옵니다.

! [rejected] main -> main (fetch first) error: failed to push some refs to 'https://github.com/…'

에러처럼 보이지만 정상 동작입니다. GitHub에 내 컴퓨터에 없는 팀원의 기록이 있어서, Git이 그 기록을 덮어쓰지 않도록 막은 것입니다. 먼저 받아와서 합친 뒤 다시 올리면 됩니다.

$ git pull --no-rebase $ git push
  • divergent branches 안내가 나오면서 pull이 멈출 때 --no-rebase를 붙입니다. 한 번 git config --global pull.rebase false를 해 두면 매번 붙이지 않아도 됩니다.
  • 합치는 기록의 메시지를 묻는 vi 화면이 열리면 Esc → :wq → 엔터를 누르면 저장되고 닫힙니다.
  • 다른 메시지가 나올 때는 문제해결의 에러 사전에서 찾아보세요.

branch로 따로 작업하기

branch는 기록의 갈래입니다. 모두가 보는 main은 그대로 두고, 내 작업은 나만의 갈래에서 진행한 뒤 다 되면 main에 합칩니다. 이렇게 하면 작업이 서로 섞이지 않고, 합치기 전에 팀원이 한 번 검토할 수 있습니다.

$ git switch -c feature/menu $ git branch $ git push -u origin feature/menu
  • git switch -c 이름 : branch를 만들면서 그 branch로 이동합니다. 이름은 feature/메뉴처럼 무슨 작업인지 알 수 있게 짓습니다.
  • git branch : branch 목록을 보여 줍니다. *가 붙은 것이 지금 있는 branch입니다.
  • git push -u origin 이름 : 새 branch를 GitHub에 처음 올릴 때 한 번 씁니다. 그 뒤로는 git push만 쳐도 됩니다.

branch에서 작업하는 동안에도 수정, add, commit은 개인 작업과 똑같이 합니다.

꼭 branch를 써야 하나요?

작은 프로젝트에서는 main에 바로 push하기도 합니다. 다만 여럿이 같은 파일을 동시에 고치면 충돌이 자주 나서, 팀이 정한 규칙이 있다면 그것을 따르세요. 규칙이 없다면 branch를 쓰는 편이 안전합니다.

Pull Request로 합치기

Pull Request(PR)는 “내 branch의 작업을 main에 합쳐 주세요”라고 GitHub에서 요청하는 기능입니다. 명령어가 아니라 GitHub 화면에서 합니다.

  1. 1
    branch를 push합니다위에서 한 git push -u origin 이름입니다.
  2. 2
    PR을 엽니다repo 화면에 노란 Compare & pull request 버튼이 나타납니다. 누르거나, Pull requests 탭에서 New pull request를 누릅니다.
  3. 3
    제목과 설명을 적고 Create pull request무엇을 바꿨는지 짧게 적습니다. 오른쪽 Reviewers에서 검토해 줄 팀원을 고를 수 있습니다.
  4. 4
    팀원이 확인합니다Files changed 탭에서 바뀐 줄을 초록(추가)과 빨강(삭제)으로 볼 수 있고, 줄마다 댓글을 달 수 있습니다.
  5. 5
    합칩니다초록색 Merge pull request → Confirm merge를 누르면 main에 합쳐지고 PR에 보라색 Merged가 표시됩니다.

누가 merge할지는 팀마다 다릅니다. 소유자만 하거나, 검토를 받은 뒤 작성자가 직접 하기도 하니 팀에서 정해 두세요. merge가 끝나면 PR 화면의 Delete branch로 다 쓴 branch를 지워도 됩니다.

합친 뒤 내 컴퓨터 정리하기

GitHub의 main이 바뀌었으니, 내 컴퓨터도 main으로 돌아와 새 내용을 받아옵니다.

$ git switch main $ git pull $ git branch -d feature/menu 내 컴퓨터의 다 쓴 branch를 지웁니다 (합쳐진 branch만 지워집니다)

충돌이 났을 때

나와 팀원이 같은 파일의 같은 부분을 다르게 고치면 Git이 어느 쪽을 남길지 알 수 없어서 합치기를 멈춥니다. 이것이 충돌(conflict)입니다. 고장이 아니라 “사람이 골라 주세요”라는 요청입니다.

pull이나 merge를 할 때 이런 메시지가 나옵니다.

CONFLICT (content): Merge conflict in memo.txt Automatic merge failed; fix conflicts and then commit the result.

충돌한 파일을 열면 Git이 두 내용을 표시해 둔 것을 볼 수 있습니다.

<<<<<<< HEAD 내가 고친 줄 ======= 팀원이 고친 줄 >>>>>>> origin/main
  1. 1
    충돌한 파일을 엽니다git status의 both modified 목록에서 파일을 찾을 수 있습니다.
  2. 2
    남길 내용으로 고칩니다내 것, 팀원 것, 둘을 섞은 것 중 하나로 정리하고 <<<<<<<, =======, >>>>>>> 세 줄은 반드시 지웁니다. 어떻게 할지 모르겠으면 팀원에게 물어보세요.
  3. 3
    저장하고 add, commit합니다git add 파일이름 → git commit -m "충돌 해결"
  4. 4
    git push합친 결과를 올립니다.

충돌을 줄이려면 같은 파일을 여럿이 동시에 고치지 않고, 자주 pull하는 것이 가장 효과적입니다.

팀 작업 습관

이것만 지켜도 사고가 줄어듭니다

  • 작업을 시작하기 전에 항상 git pull합니다.
  • commit은 작게, 메시지는 알아볼 수 있게 씁니다.
  • 같은 파일을 팀원과 동시에 고치지 않도록 맡는 부분을 나눕니다.
  • git push --force는 쓰지 않습니다. 팀원의 기록을 지워 버릴 수 있습니다.
  • 비밀번호, 키 같은 비밀 정보는 올리지 않습니다. (개인 작업의 .gitignore 참고)
  • 막히거나 실수했을 때는 당황하지 말고 문제해결부터 찾아봅니다.
