05 · 문제해결

문제해결

작업하다 막혔거나 실수했을 때 찾아보는 페이지입니다. 되돌리는 방법과 에러 메시지의 뜻을 모았습니다.

이 페이지의 순서

  1. 1상황별로 찾기이럴 땐 이 명령
  2. 2되돌리기restore, reset, revert
  3. 3에러·안내 메시지 사전메시지별 뜻과 해결

상황별로 찾기

자주 겪는 상황에 맞는 명령을 골랐습니다. 자세한 설명은 아래 섹션에 있습니다.

이럴 땐이 명령
git status지금 상태가 헷갈릴 때 가장 먼저 칩니다.
git log --oneline지금까지 쌓인 commit 기록을 한 줄씩 봅니다.
git diff무엇이 어떻게 바뀌었는지 줄 단위로 봅니다.
git restore --staged 파일add를 잘못했을 때 취소합니다.
git restore 파일고친 내용을 버리고 되돌립니다.주의
git reset --soft HEAD~1push 전에 방금 commit을 취소합니다.
git revert HEAD이미 push한 commit을 취소하는 새 commit을 만듭니다.
git pull팀원이 올린 작업을 받아옵니다.
git pull --no-rebasepush가 거절되고 divergent branches 안내가 나올 때 씁니다.

명령 자체가 낯설다면 명령어 모음에서 먼저 찾아보세요.

되돌리기

실수했을 때 쓰는 명령입니다. 어느 단계까지 갔는지에 따라 쓰는 명령이 달라집니다.

push 전과 후는 다릅니다

  • push 전 : 내 컴퓨터에만 있는 기록이라 amend, reset으로 고쳐도 됩니다.
  • push 후 : 이미 팀원이 받아 갔을 수 있으니 기록을 지우지 말고, revert로 취소하는 새 commit을 만드세요.
명령하는 일
git restore 파일이름고친 내용을 버리고 마지막 commit 상태로 되돌립니다. 버린 내용은 복구할 수 없습니다.주의
git restore --staged 파일이름add를 취소합니다. 파일 내용은 그대로입니다. (commit이 없는 새 repo에서는 git rm --cached 파일이름)
git commit --amend -m "새 메시지"방금 commit의 메시지를 고칩니다. push하기 전에만 씁니다.
git reset --soft HEAD~1방금 commit을 취소합니다. 변경 내용은 스테이징에 남습니다. push하기 전에만 씁니다.
git reset HEAD~1방금 commit을 취소합니다. 변경 내용은 작업 폴더에 남고 add는 풀립니다. push하기 전에만 씁니다.
git reset --hard HEAD~1방금 commit과 그 변경 내용을 모두 지웁니다. 복구하기 어렵습니다.주의
git revert HEAD방금 commit을 취소하는 새 commit을 만듭니다. 이미 push한 뒤에도 안전합니다.
git rm --cached 파일이름Git이 추적하는 것만 멈추고 내 컴퓨터의 파일은 남깁니다. .gitignore에 적기 전에 이미 commit한 파일에 씁니다.
git check-ignore -v 파일이름어느 .gitignore 규칙이 그 파일을 무시하는지 알려 줍니다. 아무것도 안 나오면 무시되지 않는 것입니다.

주의가 붙은 명령은 내용을 영영 지울 수 있습니다. 확신이 없으면 치기 전에 git status와 git log --oneline으로 상태를 먼저 확인하세요.

에러·안내 메시지 사전

메시지의 앞부분이나 핵심 문장으로 찾으세요. … 자리에는 파일이나 branch 이름이 들어갑니다. hint:로 시작하는 줄은 Git이 알려 주는 해결 방법이니 같이 읽어 보세요.

메시지뜻해결
fatal: not a git repository (or any of the parent directories): .git지금 있는 폴더가 Git 저장소가 아닙니다. repo 폴더 밖에서 git 명령을 쳤습니다.pwd로 위치를 보고 cd로 repo 폴더 안으로 이동합니다.
zsh: command not found: git / 'git' is not recognizedGit이 설치되어 있지 않거나 터미널이 찾지 못합니다.설치 페이지를 따라 Git을 설치한 뒤 터미널을 껐다 켭니다.
nothing to commit, working tree clean에러가 아닙니다. 바뀐 파일이 없다는 뜻입니다.할 일이 없습니다.
nothing added to commit but untracked files present새 파일은 있는데 add를 하지 않았습니다.git add 파일이름 후 commit합니다.
fatal: pathspec '…' did not match any files적은 파일 이름을 찾지 못했습니다. 오타이거나 다른 폴더에 있습니다.ls로 파일 이름을 확인하고 Tab 자동완성을 씁니다.
Aborting commit due to empty commit message.commit 메시지 없이 vi를 빠져나와서 commit이 취소되었습니다.git commit -m "메시지"로 다시 칩니다.
Author identity unknown / *** Please tell me who you are. / fatal: unable to auto-detect email addresscommit에 남길 이름과 이메일이 설정되어 있지 않아 commit이 만들어지지 않았습니다. (기록은 저장되지 않았으니 걱정하지 않아도 됩니다.)이름과 이메일을 한 번 설정한 뒤 git commit -m "메시지"를 다시 칩니다.
git config --global user.name "이름"
git config --global user.email "메일주소"
메일은 GitHub 계정에 등록한 이메일, 또는 GitHub가 알려 주는 noreply 주소를 씁니다.
error: src refspec main does not match anycommit이 하나도 없거나 branch 이름이 main이 아닙니다.commit을 한 뒤 push합니다. git branch로 branch 이름을 확인합니다.
fatal: The current branch … has no upstream branch.이 branch를 GitHub의 어느 branch와 연결할지 정해지지 않았습니다.안내문에 나온 git push --set-upstream origin 이름을 그대로 칩니다.
! [rejected] main -> main (fetch first)GitHub에 내 컴퓨터에 없는 commit이 있어서 push가 막혔습니다.git pull 후 다시 git push합니다.
fatal: Need to specify how to reconcile divergent branches.내 기록과 GitHub 기록이 갈라져 있어 합치는 방식을 정하라는 안내입니다.git pull --no-rebase를 칩니다. 이후 계속 쓰려면 git config --global pull.rebase false를 설정합니다.
error: Your local changes to the following files would be overwritten by mergecommit하지 않은 내 변경이 pull로 덮어써질 수 있어서 막혔습니다.변경을 먼저 commit하거나 git stash로 치워 두고 pull합니다.
CONFLICT (content): Merge conflict in …같은 파일의 같은 부분을 나와 팀원이 다르게 고쳤습니다.파일을 열어 <<<<<<<, =======, >>>>>>> 표시를 정리하고 저장한 뒤 add, commit합니다.
fatal: refusing to merge unrelated histories서로 기록이 이어지지 않는 두 저장소를 합치려 합니다. 각각 따로 만든 repo를 연결할 때 나옵니다.팀원에게 확인한 뒤, 정말 합쳐야 한다면 git pull --allow-unrelated-histories를 씁니다.
fatal: remote origin already exists.이미 GitHub 주소가 연결되어 있습니다.git remote -v로 연결된 주소를 확인합니다.
fatal: Authentication failed / Support for password authentication was removedGitHub는 계정 비밀번호로 push하는 것을 허용하지 않습니다.브라우저 로그인 창이나 Personal Access Token(토큰)을 비밀번호 자리에 입력합니다.
Permission denied / fatal: unable to access … 403이 repo에 올릴 권한이 없습니다.소유자에게 Collaborator로 초대받았는지 확인하고, 초대 메일이나 GitHub 알림에서 수락합니다.
remote: Repository not found. / fatal: repository '…' not foundGitHub가 그 주소의 repo를 찾지 못했습니다. 주소에 오타가 있거나, repo 이름이 바뀌었거나, 비공개 repo인데 내 계정에 권한이 없을 때 나옵니다. (권한이 없는 비공개 repo는 “없다”고 알려 줍니다.)git remote -v로 연결된 주소를 보고 GitHub 화면의 주소와 글자 하나까지 비교합니다. 다르면 git remote set-url origin 올바른주소로 고칩니다. 주소가 맞다면 Collaborator 초대를 수락했는지, 컴퓨터에 저장된 로그인이 다른 계정은 아닌지 확인합니다.
warning: LF will be replaced by CRLFWindows와 맥의 줄바꿈 방식이 달라서 나오는 안내입니다.오류가 아니므로 무시해도 됩니다.
